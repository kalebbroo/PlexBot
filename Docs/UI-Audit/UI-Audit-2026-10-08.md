# UI and UX audit (2026-10-08)

Audit only. No code was changed. Live captures are in `screenshots/`, taken in KalebKorp `#testing` on the `Plex Bot` build from `cd9375a`.

## Summary

The bot already uses Components V2 and has a custom emoji progress bar, so the base is good. The gaps are:

1. **The Visual Player is the only polished surface.** Everything else is plain text in grey containers with a single accent colour.
2. **The help screen has no pictures, no tutorial, and misses most features.** Several bots' `/help` appear in the Discord picker, so ours is hard to find.
3. **Buttons are icon-only and mostly the same grey.** Four icons (🔉 📻 🔍 🧭) have no label, so their meaning isn't clear.
4. **Two confirmed bugs in the UI state** (see "Bugs found during the audit").
5. **Dead code.** `DiscordEmbedBuilder` (all of it) and `BuildPlayerEmbed`/`BuildQueueEmbed` have no callers. The bot is effectively all Components V2 now.

## Per-surface findings and plan

### 1. Visual Player (modern) — the main surface

Live capture: `screenshots/01-visual-player-zoom.png`

What works: the 16:9 artwork card, title and artist, progress bar, "Next Up" column, and the volume bar on the image.

Issues:
- **Two rows of icon-only buttons.** Row 1 has 🔉 ⏸️ ⏭️(Skip) 🔁 📋(Queue Options). Row 2 has 🔉 📻 🔍 🧭 ⏹️(Kill). Only Skip, Queue Options and Kill have labels, so the row is inconsistent.
- **Duplicate volume buttons** (🔊 and 🔉 on different rows) with no visible volume level on the button itself. The level is on the image.
- **Adventure (🧭) and Similar (🔍)** are unlabelled and their meaning isn't obvious. The live capture shows a second 🔍 button in the search panel as well.
- **No button state beyond repeat.** Pause/resume is a different emoji, but there's no colour change, and shuffle has no state at all.
- **Kill is the only red button**, which is right, but the stop action has no confirmation.
- **Status line** shows only the progress bar. Volume and repeat are on the image, so the image carries too much.
- **"[&]" under the artist** on the captured track is the album title from Plex metadata (`ImageBuilder.cs:267`). Not a bug.
- **Stale after kill (bug 1, fixed in PR 1).**

Plan:
- Use the same button style for the whole player. Give each button a label and an emoji, keep at most one row of primary controls, and move the rest to a "More" menu or a second row with labels.
- Show volume and repeat as text in the status line, not only on the image.
- Add a custom "player" emoji set (see the emoji section) for play, pause, skip, volume, repeat, shuffle, radio, similar and adventure.
- Add an "idle" state rendered by the same builder, so a killed player turns into a clear "Stopped. Use /play" card with no live controls.

### 2. Visual Player (classic) and 3. Idle player

Classic is a fallback when the image is off. It uses a small thumbnail section, which is fine. It has no custom emoji, and the buttons aren't labelled.

Plan: give both the same layout and emoji as the modern player, so switching modes isn't a visual change. The idle player should show the banner (`Images/PlexBotBanner.png`, currently only used in the README) and a one-line "How to start" line.

### 4. Progress bar

Works well. Custom emoji are used, and the unicode fallback works.

Plan: keep the custom-emoji approach and extend it to every icon in the bot. Right now the 30 IDs are all for the bar, so the custom set is small. Only the bar and the time chips use it.

### 5. Status messages

Live capture: `screenshots/02-similar-and-tracks-added.png` (✅ "Tracks Added" card).

What works: consistent accent colour per type, short title and body.

Issues:
- **Wording is inconsistent.** "Please wait a moment before clicking again" appears in 8 places. "Playback Error" is used for three different failures.
- **No next step.** An error says what failed but not what to do, and there are no buttons (e.g. "Try again", "Open help").
- **Emoji from unicode.** ✅ ❌ ℹ️ ⚠️ are different in style from the rest of the design.
- **Some messages are ephemeral and some aren't**, with no consistent rule.

Plan:
- Write one message catalogue (title, body, optional button) and reuse it for all of them.
- Give each status a custom emoji (success, error, info, warning) so they match the player.
- Add a retry or help button where one makes sense.

### 6. `/search` results and 7. Sonic results (similar, radio, mood, genre, adventure)

Live capture: `screenshots/02-similar-and-tracks-added.png` ("Similar to: Bohemian Rhapsody", select menu, "Play All Similar" button).

What works: the select menu and "Play All Similar" are clear. Option descriptions show artist and album.

Issues:
- **No artwork or preview.** Select menus show text only.
- **Only 25 options**, with no paging. A search for a big artist truncates silently.
- **Placeholder "Select a similar track to play"** is the same for every result type.
- **Each result type has its own header wording**, with no shared look.

Plan:
- Show a thumbnail or a grid of artwork in the container, with the select menu below as the picker.
- Add a "Next page" button where results exceed 25.
- Give each result type its own emoji header (🔍 search, 📻 radio, 🧭 adventure, 🎵 similar), using the custom set.

### 8. Queue display and 9. Queue options panel

Queue Options is an ephemeral panel with three buttons (View, Shuffle, Clear). The queue display shows titles and durations, with a footer line.

Issues:
- **Queue options shows "No active player" once the player is gone**, which is accurate but dead-ends the user (see the bug below).
- **The queue is text only.** There's no artwork, no icons for the current track, and the placeholder titles don't say they are still loading (they resolve later).
- **Pagination buttons** have no page indicator other than the footer line.

Plan:
- Add a "Now playing" card with artwork and a "Queue" card below it. Mark unresolved items with a loading icon, not just a title.
- Keep the panel ephemeral, but add a "Close" button.

### 10. Radio options panel

Shows a seed track and a "Start Radio" header. Its buttons are the same as the queue options.

Plan: show the seed track's artwork in the container. Use the 📻 custom emoji in the header.

### 11. Help and 13. Slash command names and descriptions

Live capture: `screenshots/03-help-current.png` (the Plex Bot `/help` card). Picker: `screenshots/04-help-picker-collisions.jpg`.

Issues:
- **Shows three commands only.** `/ping` is missing, and the sonic features (radio, similar, adventure, mood and genre search) are not mentioned at all.
- **Plain text.** No images, no steps, no button to try things.
- **Several bots answer `/help`.** The picker lists `/help` from at least four other bots as well as ours (`04-help-picker-collisions.jpg`). Ours is only identifiable by the "Plex Bot" label under it. Command names are global in the picker, so a clearer name (e.g. `/plexhelp` or `/music help`) would help.
- **Slash descriptions are short and inconsistent.** "Test if interactions are working" is a dev command shown to every user. The `[Summary]` attributes on the parameters are only on five commands, and they're missing from the parameters of `/playlist` and `/play`.

Plan (this is the requested rewrite):
- A help hub with a select menu of topics: "Start playing", "Player controls", "Search and discovery", "Queue", "Radio and sonic", "Troubleshooting".
- Each topic is a Components V2 card with a screenshot from `Images/` and one or two buttons (e.g. "Try /playlist" opens the search flow).
- A short "tutorial" that walks through the first `/playlist` and the player buttons, using the captured screenshots.
- Hide `/ping` from normal users, or make it admin-only.
- Give every parameter a description and a short example.

### 12. Sonic Adventure modal

Code: `SonicAdventureModal`, title "Sonic Adventure", one field "Destination Track", placeholder "Enter a track name to travel to...", max 200.

Issues:
- **No explanation.** The modal doesn't say what the adventure does (builds a path from the current track to the destination).
- **Plain title**, no emoji. Discord modals can't show images, so the explanation has to be in the placeholder or in the field label.

Plan: retitle to "🧭 Sonic Adventure", and make the label "Where should the path end?" with a placeholder like "e.g. Bohemian Rhapsody". Post a short intro card before the modal opens.

### 14. Autocomplete

Works. Not reviewed in detail. Plan: show artwork-less text with the artist in brackets, which it already does; check the option text is under 100 characters.

### 15. Legacy embeds (dead code)

`DiscordEmbedBuilder.cs` defines Success, Error, Info, Warning, SearchResults, CommandError, BuildPlayerEmbed and BuildQueueEmbed. No caller references the class.

Plan: delete it in the redesign PR. Move any colours it defines into the shared design tokens (see below).

## Emoji plan

Currently: 30 custom emoji for the progress bar (in config), and unicode for everything else.

Proposed set (one custom emoji each, prefix `pb_`):

- **Player controls:** play, pause, skip, previous, stop/kill, repeat (off/track/queue), shuffle, volume up, volume down
- **Features:** radio, similar, adventure, search, queue, playlist, plex
- **Status:** success, error, info, warning, loading
- **Brand:** the logo as a server emoji, used in the help header

Each emoji is uploaded to the server and its ID goes in `config.fds`. The existing `ComponentV2Builder` loader is the pattern to copy. A missing ID falls back to the unicode emoji, so nothing breaks while the set is being built.

Note: the server needs the emoji uploaded before the help screenshots, since the screenshots show what the emoji look like.

## Design tokens

Colours are currently hard-coded in two places (`DiscordEmbedBuilder` and `ComponentV2Builder`), and they are the same values. Move them into one `DesignTokens` class: one accent for music, one for each status, one for help. Use the same tokens for the image rendering in `ImageBuilder`, so the image and the card match.

## Bugs found during the audit

1. **Visual Player stays live after Kill.** The log shows `Player killed by kalebbroo` at 19:10:19. The `Dance on My Own` player message stayed in `#testing` with live buttons. Clicking Queue Options then returned "No Player: No active player found" (`06-queue-options-no-player.jpg`). Confirmed cause: nothing published `player.destroyed` at all. `EventHandler.cs:149` subscribed to it for the bot status, but no code called `PublishAsync` for it, so no subscriber ever ran. **Fixed in PR 1:** `PlayerService.StopAsync` and the inactivity timeout now publish it, and `VisualPlayer.HandlePlayerDestroyedAsync` replaces the message with a stopped card (or the idle card with a static channel).
2. **Sonic Adventure button says "Not Available" while a Plex track was playing** (`05-adventure-not-available.jpg`). The handler at `MusicInteractionsHandler.cs:620` returns that message when `GetPlayerAsync` isn't a `CustomLavaLinkPlayer`, or when `CurrentItem` isn't a `CustomTrackQueueItem`, or when the source isn't Plex. Cause: the guard used one generic message for two cases. The player had already been killed (bug 1), so `GetPlayerAsync` returned nothing, and the message said "Play a Plex track first". Queue Options returned "No active player" for the same state. **Fixed in PR 1:** the guard now says "No active player" when there is no player, and keeps "Not Available" for non-Plex tracks.
3. ~~The Visual Player message shows "[&]"~~ Not a bug: it is the album title from Plex metadata.
